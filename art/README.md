# Smithing artwork

`smithing_art.py` is the editable pixel-art source: named material ramps, hand-placed 16×16 item pixels, block material clusters, four molten frames, particles and GUI sheets. No stochastic noise, smooth resampling or placeholder synthesis is used.

- `python3 tools/generate_textures.py` (or `--check`) compares exports, without writing anything.
- `python3 tools/generate_textures.py --write` explicitly exports the finished artwork to the resource folder. Change the source first.
- Station and decorative mesh sources are the Java Block/Item JSON files in `src/main/resources/assets/immersive_smithing/models/block/`. Open these directly in Blockbench using **File → Import → Java Block/Item**. Each face has explicit UVs at one texel per model unit. North is the front; rotations live in blockstates. Keep the matching `StationShape` definitions in sync if changing geometry. Static station meshes retain their cuboid and face limits (forge 14 / 84, anvil 10 / 60, trough and grindstone 7 / 42 each): bands, straps and rivets are painted on `block/anvil_stump` and `block/trough_staves` rather than modelled. The moving bellows (2 cuboids / 10 faces) and five-course wheel (5 cuboids / 30 faces) have separate budgets. Including both moving meshes, the four stations use 40 cuboids / 192 faces against a combined 40 / 228 limit; the rounded wheel adds two cuboids and fourteen faces. The wheel stays inside its original bounds; its cached picking shape follows the same five courses. `python3 tools/model_preview.py --check` enforces the static and moving budgets and that every blockstate, model and texture resolves; `--stats` prints the counts and the default mode renders isometric previews.
- All item transforms remain resource-pack replaceable. Loaded tongs draw the actual workpiece at the metal jaw gap, using its profile, target blade silhouette and heat; the tier model supplies the handle transforms. The retained fallback loaded models use Forge's standard `forge:item_layers` with only layer 1 emissive. For Forge 47.4.23 the data is nested under `forge_data.layers`, keyed by the layer number; the validation command checks this contract. No shader pack is needed.
- Decorative meshes (`metal_billet`, `fuel_chunk`, `hot_billet`, `hot_plate`, `hot_blade`) are registered as additional baked models and resolved from the current model manager after reload. Textures likewise come from the current block atlas.
- GUI atlas contract: `gui/smithing.png` (256×256) holds only the anvil minigame's target ring `(96,0,64,64)` and disc `(160,0,64,64)`; everything else on the sheet is transparent and unused. Since 1.1.0 the screens draw Minecraft's own GUI textures (`demo_background`, `generic_54` slots, `widgets` buttons, the creative scroller, `furnace` arrows and the written-book page `book`), so a resource pack's versions of those textures apply to them; text colours are vanilla's defaults and are not taken from the pack. The retired theme sheets `gui/stone.png`, `gui/slot.png` and `gui/guide.png` must not return: `tools/generate_textures.py` fails its check while any of them exists, and `--write` deletes them.

Palette: blue-grey worked iron, soot-dark masonry, warm worn timber, small bronze fasteners, ivory/yellow/orange hot metal. Shapes, labels and timer marks accompany color. Station geometry supplies the silhouette; pixels supply grain, seams, wear and fasteners.

References: [Blockbench Minecraft Style Guide](https://blockbench.net/wiki/guides/minecraft-style-guide/), Forge 1.20.1 [block entity renderers](https://docs.minecraftforge.net/en/1.20.1/blockentities/ber/), [screens](https://docs.minecraftforge.net/en/1.20.1/gui/screens/), [emissive face data](https://docs.minecraftforge.net/en/1.20.1/rendering/modelextensions/facedata/).

The visual refinement keeps the original editable source and 16×16 material grid. Stone uses chipped courses with narrow mortar; timber uses low-contrast interrupted grain; iron uses small hammer scuffs. The anvil bevel and wheel rings are placed inside the UV areas actually sampled by those models. Workpiece UVs use object coordinates so grain continues across segments. Flat blade targets also supply their opaque silhouette for shaping; the shaped metal and finished item share a measured pose, retained with the output across anvil saves and updates. Dished profiles have joined upper and lower facets and sit above the anvil; picking and chalk use the same cross-section.

`runClient -PsmokeTest` also captures `packtest_workpiece_profiles.png`, a test-only gallery of all 13 shipped profiles at half and full shaping. It checks surface height, facet continuity and picking at zero, half and full shaping. This fixture is confined to `src/packTest` and is not shipped in the production jar.
